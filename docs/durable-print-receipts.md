# 永続的な印刷受付記録（opt-in）

`RAKUSIKA_PRINT_RECEIPTS_DIR`に永続ディスク上の専用ディレクトリを指定し、POST /printer/printへ16〜128文字の`Idempotency-Key`を付けると有効。同じ物理プリンターを扱うプロセスは同じ記録ディレクトリを使う。記録にはラベル内容のコピーを含めず、要求ハッシュとHTTP結果を保持する。ディレクトリ0700・ファイル0600。

排他的作成した受付記録と親ディレクトリをfsyncしてから既存印刷処理を一度だけ呼ぶ。結果はfsyncとatomic renameで保存する。同じID・内容の再送には保存した結果を返す。内容が異なる場合409。処理途中・破損・結果保存失敗はPRINT_OUTCOME_UNKNOWNで停止し、物理印刷を自動再実行しない。部分印刷エラーも記録して同じIDでは繰り返さない。明示的な再印刷は出力・キューを確認したうえで新しいIDを発行する。

再起動後も記録を保持する。TTLや自動削除はしない。応答がpendingの場合、再送結果は受付時のpendingであり、その後のCUPS状態は既存ジョブ照会APIで確認する。doneも利用者の目視確認を代替しない。

設定なしでID付き要求を受けた場合503で印刷前に停止。ヘッダーなしの既存LAN APIは従来どおり。既存LAN制限内で動作し、Bluetooth端末・施設・ユーザー認証を追加するPRではない。Lite側の要求ID永続化とUI連携、実機再起動試験は別途必要。

ロールバック時は記録ディレクトリを残す。旧バイナリはIdempotency-Keyを認識しないため、未確定要求を旧バイナリへ再送しない。クライアントの新経路を止めてジョブ状態・実物を確認してから旧バイナリへ戻す。実機では配備前のバイナリSHAと設定を固定し、復旧後health・計量接続・レンダリングを検証する。

自動検証: 再起動を模した新ハンドラー、同時送信、途中panic、部分失敗、新IDでの明示再実行、永続化設定なし、不正ID/JSON、破損記録、旧呼び出しをテスト。実機部分印刷は別証拠としてOfficeジョブ304、補充後の正常印刷は305を記録。
