# QL-820NWB のエラーと、タブレットに出す案内

rakuql（`internal/printer/qlbackend`）は、プリンタが USB で返す 32 バイトの状態フレームを
1 枚ごとに読み、何が起きたかをタブレットに返す。この表は、その対応の一覧。

- 「定義」は Brother QL-800 シリーズのラスタコマンドリファレンス（brother_ql の読み方と同じ）
- 「実例」は拠点・office で実際に見たもの
- 受信したフレームはすべて journal に残る（`sudo journalctl -t rakuql`、v0.3.33 から）

## プリンタがエラーとして知らせるもの

状態フレームの byte 8（エラー情報 1）と byte 9（エラー情報 2）のビット。

| ビット | 定義 | タブレットの文言 | 実例 |
| --- | --- | --- | --- |
| err1 0x01 | 用紙なし | ロールが入っていません。ロールを入れてください。 | |
| err1 0x02 | 用紙の終わり | **用紙を送れません。ロールが引っかかっていないか、終わっていないかを確かめ、正しくセットし直してください。** | office 2026-10-07 ×2。ロールは残っていて、ローラーの糊で引っかかっていた。プリンタの画面も「用紙を送れません」 |
| err1 0x04 | カッターの詰まり | カッターが詰まっています。詰まったラベルを取り除いてください。 | |
| err1 0x10 | 使用中 | （エラーではない。1 秒おきに問い合わせ直す） | |
| err1 0x80 | ファン故障 | プリンタのファンが動いていません。プリンタの電源を入れ直し、直らなければ修理を依頼してください。 | |
| err2 0x01 | ロールとデータの不一致 | 装着されているロールと印刷データが一致しません。ロールを確認してください。 | 非純正ロールでは照合を切る（`PRINTER_ROLL_CHECK=off`） |
| err2 0x02 / 0x08 | 受信バッファがいっぱい | プリンタの受信バッファがいっぱいです。 | |
| err2 0x04 | 通信エラー | プリンタとの通信でエラーが起きました。 | |
| err2 0x10 | カバーが開いている | カバーが開いています。カバーを閉じてください。 | office 2026-09-25 |
| err2 0x40 | 用紙を送れない | err1 0x02 と同じ | |
| err2 0x80 | 本体のエラー | プリンタ本体でエラーが起きました。プリンタの電源を入れ直してください。 | |
| （ビットなしのエラー） | 理由を言わずに止まった | プリンタがエラーを報告しました（コード xxxx）。プリンタの画面の表示とロールを確認してください。 | 函館 2026-09-27〜29（赤黒 2 色ロールに黒だけのデータ。今は自動で 2 色に変換して送る） |

### 印刷中のエラーのあと、プリンタが黙ることがある

office で 2 回、印刷中の「用紙を送れません」のあと、プリンタは状態の問い合わせに
一切答えなくなった。ロールを直しても、USB をリセットしても戻らず、電源の入れ直しでだけ戻った。

そこで印刷中にエラーが来たら、プリンタの受信内容を消したあと問い合わせ、答えなければ次の 1 文を足す。

> プリンタが応答しなくなっています。直したあと、プリンタの電源だけを入れ直し（タブレットの電源は切らないでください）、プリンタが起動してから再送信してください。

## プリンタが知らせない失敗

| 起きたこと | rakuql の判定 | タブレットの文言 | 実例 |
| --- | --- | --- | --- |
| 印刷前の問い合わせに答えない | 送るだけ送り、「確認できない」で返す | 印刷データは送りましたが、プリンタが応答しないため印刷できたか確認できません。ラベルが出ていなければ、プリンタの電源だけを入れ直し…再送信してください。 | office 2026-09-25（CUPS の usb バックエンドが通知を読み残した後）、2026-10-07（用紙を送れないエラーの後） |
| データを受け取ったまま、印刷完了を知らせない | 1 枚 20 秒で問い合わせ。答えるか答えないかで文言を分ける | プリンタから印刷完了の知らせが届きませんでした（N 枚中 M 枚）。＋「ラベルが出ていれば再送信は不要…」または「プリンタが応答しなくなっています…」 | シクヌ 2026-10-05, 10-06, 10-07、函館 2026-10-06。原因は調査中（journal の `probe:` 行で切り分ける） |
| 問い合わせると完了が遅れて届く | 印刷済み | 印刷しました。 | |
| ヘッドの冷却 | 3 分まで待つ | （途中経過のみ） | |
| 印刷中に USB が切れた | 失敗 | 印刷中にプリンタとの接続が切れました。プリンタが起動し終わるのを待ち、電源と USB ケーブルを確認してから、ラベルを確かめて再送信してください。 | 函館 2026-10-06（プリンタを入れ直している最中の再送） |
| 印刷中に電源が切れた | 失敗 | 印刷中にプリンタの電源が切れました。ラベルを確かめてから再送信してください。 | |
| データを受け取らない（書き込みが 15 秒止まる） | 失敗 | プリンタが印刷データを受け取りません。プリンタの電源だけを入れ直し…再送信してください。 | |
| USB にプリンタが見つからない | 5 秒待って失敗 | プリンタ（シリアル …）が USB に見つかりません。電源と USB ケーブルを確認してください。 | |
| ほかの処理がプリンタを開いている | 90 秒まで待つ | プリンタがほかの処理に使われたままです…しばらく待ってから再送信してください。 | |

## タブレット側

hub は `PRINTER_ERROR:` / `PRINTER_PAPER_ERROR:` / `PRINTER_UNAVAILABLE:` を頭に付けて返す。
raku-sika-lite はこれを `HUB_PRINTER_ERROR` として、上の文言をそのまま本文に出す。
手順欄は共通（ラベルを確かめる → 再印刷 → プリンタの電源だけ入れ直す）。
